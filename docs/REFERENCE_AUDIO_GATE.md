# 参考音质量门禁（客观、可复现、不靠耳朵）

## 一、为什么要做门禁

产品里每一个音色能力都以一段参考录音为条件：零样本合成的提示音、kNN-VC 的匹配池、
歌声转换的目标音色。参考音一旦有问题，**所有能力同时变差**——削波、底噪、窄带
（电话录音升采样）会一起被学进音色，而失败只表现为「听起来变差了」。

这正是本项目明确不做的判断方式。所以门禁是一组**确定性 DSP 测量**，不是听感打分。
它回答三个问题：

1. **这段录音能不能用？** 削波、直流偏置、数字静音、电平过低是硬缺陷，训练补不回来。
2. **干净语音够不够长？** 需要的长度不是录音的属性，而是**用途**的属性：
   合成提示音放一句话，kNN-VC 匹配池要成分钟。所以调用方必须声明 `purpose`。
3. **高频还在不在？** 从电话录音升采样得到的文件保留了采样率，却完全没有 4 kHz 以上的能量，
   摩擦音（s/ʃ/f）已经不存在。**看采样率看不出来，必须测内容。**

## 二、测什么（每条都有明确定义）

| 指标 | 定义 | 为什么这样定义 |
| --- | --- | --- |
| `duration_seconds` | 时长 | 用途相关，见第四节 |
| `clipping_ratio` | `\|x\| ≥ 0.999` 的样本占比 | 单独用会误判，见下 |
| `clipping_run` | 满量程**连续**样本的最长长度 | 区分「硬削波」与「正常归一化」 |
| `dc_offset` | 样本均值 | 占用动态范围、带来低频撞击 |
| `peak_dbfs` / `rms_dbfs` | 峰值 / 有效值 | 电平过低会被噪声底掩盖 |
| `silence_ratio` | 静音帧占比（25 ms 帧、35 dB 相对峰值） | 静音太多等于可用语音很少 |
| `estimated_snr_db` | 语音电平（帧 RMS 第 70 百分位）− 噪声底（第 5 百分位） | **估计值**，非 ITU-T P.56 / WADA-SNR |
| `quiet_headroom_db` | 帧 RMS 中位数 − 第 5 百分位 | 安静帧够不够，说明 SNR 是否可信 |
| `high_band_db` | 4 kHz 以上能量 / 4 kHz 以下能量（dB） | 窄带检测，见下 |
| `rolloff_99_hz` | 99% 能量滚降频率 | **只作参考，不作判据**，见下 |

### 三个踩过的坑（每个都真的踩了）

**1. 99% 能量滚降不能当带宽判据。** 语音能量集中在 F0 与 F1，所以**完全宽带**的录音
滚降也只有 2–3 kHz。实测厂商自己的 18 条官方 prompt 滚降 1841–7764 Hz，用它当判据
会否掉一大半。真正区分宽带与「窄带升采样」的是 **4 kHz 以上到底有没有能量**。

**2. 削波占比不能区分硬削波与正常归一化。** 实测 `nanjing_female_prompt.wav` 有 2 个
样本贴顶但**最长连续只有 1 个**——这是正常峰值归一化。而厂商自己的
`tianjin_male_prompt.wav` 有 **15 个连续样本停在满量程**（971 个样本精确等于 1.0），
这是硬削波。所以判据用**连续长度**。

**3. 「先找静音帧、再用静音帧估噪声」在需要它的时候会失效。** 宽带噪声会把每一帧
都抬到静音门限之上，于是「没有静音帧」→ 估计值消失。而噪声污染恰恰就是它要抓的情况。
所以噪声底取自**帧 RMS 分布的第 5 百分位**，与语音电平（第 70 百分位）取自分布的不同位置——
早期版本对 SNR 和「动态范围」都用了第 95/5 百分位，导致两个指标**构造上必然相同**，
一个不会与另一个分歧的指标不携带任何信息。

## 三、阈值怎么定的（标定方法与实测）

阈值不是拍脑袋定的圆整数，而是**落在实测到的间隔中间**。标定用三组已知音频：

**必须通过的（不能误伤）**

| 群体 | 规模 | 时长 | 估算 SNR | `high_band_db` |
| --- | --- | --- | --- | --- |
| 厂商官方 prompt | 18 | 1.99–8.78 s（中位 2.93） | 9.6–56.2 dB（中位 23.8） | −41.7 … −12.2 |
| 用户切片语料（整体） | 64 / 281.7 s | 平均 4.4 s | **28.94 dB** | **−23.1 dB** |

**必须拦住的（构造的已知劣化）**

| 劣化 | 构造方式 | 实测 |
| --- | --- | --- |
| 窄带 | 真语音重采样到 8 kHz 再升回原采样率 | `high_band_db` = **−66.6 … −77.6 dB** |
| 硬削波 | 先归一化到满量程，再乘 3 后截断 | `clipping_run` = **32–37** |
| 噪声 | 白噪声按指定真 SNR 注入拼接语料 | 真 10 dB → 测 15.2 dB（拦）；真 20 dB → 测 23.6 dB（警告） |

由此得到的判据（**间隔都写在注释里，改阈值前先看 `backend/tests/test_reference_audio.py`
里的阈值回归测试**）：

| 判据 | 不合格 | 警告 | 间隔依据 |
| --- | --- | --- | --- |
| 高频带宽 `high_band_db` | < **−55 dB** | < −38 dB | 真实录音最低 −41.7，窄带最高 −66.6，间隔 24.9 dB |
| 削波 | 连续 ≥ **3 个**样本贴顶，或占比 ≥ 0.5% | 占比 > 0.05% | 真实归一化最长连续 1，硬削波 32+ |
| 估算 SNR | < **18 dB** | < 26 dB | 用户语料最低 24.0，注入噪声 ≤16.2 |
| 有效值 | < −34 dBFS | < −30 dBFS | 厂商最低 −31.5，用户语料最低 −25.6 |
| 直流偏置 | ≥ 2% 满量程 | — | 标准卫生阈值 |
| 静音占比 | ≥ 90% | > 60% | 标准卫生阈值 |

**SNR 只对长参考音硬拦（`snr_hard`）**，这是实测决定而非图省事：厂商自己的 18 条官方
prompt 在这个估计器上跨 **9.6–56.2 dB**，因为它们只有 2–9 秒，噪声底根本估不准。
把它当硬门禁会否掉三分之一的官方 prompt。而长参考音分布很紧（用户语料 24.0–32.2 dB），
估计既可靠又有区分度，所以那里**拦**。

### 关于 SNR 估计值的诚实说明

估计器**压缩真实 SNR**：在拼接语料上注入真 20 dB 噪声测出 23.6 dB，真 10 dB 测出 15.2 dB。
所以 18 dB 的不合格线**大致对应真实 15 dB 左右**，文档与页面都按「估计值」呈现，
不冒充认证值。这一点已写进代码注释与报告 `notes`。

## 四、用途决定时长判据

| `purpose` | 下限 | 理想 | 上限 | SNR 是否硬拦 |
| --- | --- | --- | --- | --- |
| `synthesis` | 1.5 s | 2–10 s | 20 s | 否（只警告） |
| `timbre` | 20 s | 60–300 s | 300 s | 是 |
| `singing` | 15 s | 30–300 s | 300 s | 是 |

`synthesis` 的 1.5 s 下限来自厂商自己 18 条 prompt 的 **1.99 s 最小值**——
比这更高的下限会否掉厂商发布的 prompt，按定义就是标定失败。
`timbre` 的上下限来自 kNN-VC 论文（arXiv:2305.18975，Baas / van Niekerk / Kamper,
Interspeech 2023）：参考语音不足约 30 秒质量明显退化，约 5 分钟后收益饱和。

### 语料是一个整体，不是一个文件

64 个切片每个 2–7 秒，**逐个判会全部不合格**（时长不足），而整份语料 281.7 秒完全健康。
判错单位会让门禁在最需要它的地方失效。所以 `analyze_corpus()` 按时长相加、
比例按时长加权、电平把各文件帧汇总后取分位数（避免一个 2 秒切片和一段 1 分钟录音等权）。

## 五、一个真实发现：厂商自带的 prompt 里有削波

`third_party/DiaMoE-TTS/prompts/tianjin_male_prompt.wav`：

- 2166 个样本（2.086%）≥ 0.999
- **971 个样本精确等于 1.0**
- **最长连续 15 个样本**停在满量程
- 对比 `nanjing_female_prompt.wav`：只有 2 个贴顶样本、最长连续 1

15 个连续样本停在恰好满量程，真实录音几乎不可能自然出现，这是硬削波。
**这是厂商发布数据本身的缺陷，不是标定问题**，所以门禁如实报 `fail`。
18 条官方 prompt 里最终 9 条通过、8 条警告、1 条不合格（就是这条）。

## 六、刻意不做的事

- **不做背景音乐检测，不做说话人分离（diarization）。** 做对需要独立的说话人验证模型
  与聚类，便宜的替代做法（例如「能量起伏大就是音乐」）会给出**自信的错误结论**，
  比不报更糟。本机已有 `GPT_SoVITS/GPT_SoVITS/pretrained_models/sv/pretrained_eres2netv2w24s4ep4.ckpt`
  与 `eres2net/` 代码，将来要做就用它做独立说话人一致性检查。
- **不做响度归一化**，只报告。归一化会改变用户原始素材，属于产品决策而非门禁职责。
- **不把 SNR 当认证值**，理由见第三节。

## 七、怎么用

```powershell
# 单个文件（合成提示音）
.venv\Scripts\python.exe scripts\reference_audio_check.py path\to\clip.wav --purpose synthesis

# 整份语料（音色匹配池）——注意 --corpus，判的是整体
.venv\Scripts\python.exe scripts\reference_audio_check.py --slices --corpus --purpose timbre

# 厂商官方 prompt 全量
.venv\Scripts\python.exe scripts\reference_audio_check.py --prompts --quiet

# 标定与验收（会构造窄带/削波/加噪三组已知劣化并断言判定）
.venv\Scripts\python.exe scripts\reference_audio_calibrate.py
.venv\Scripts\python.exe scripts\reference_audio_verify.py

# 回归门
.venv\Scripts\python.exe -m unittest backend.tests.test_reference_audio -v
cd frontend; npm run test -- --run src/composables/referenceAudio.test.ts
```

WebUI：设置页 → 音色样本 → 填路径或上传后点「质量检查」，先选用途。
上传时后端**仍然保存**文件并同时返回报告（`{"path": ..., "report": ...}`），
由前端决定是否拦——用户要能看着报告决定重录还是继续，而不是文件被直接丢掉。

API：

| 路由 | 用途 |
| --- | --- |
| `POST /api/reference-audio` | 上传 + 判定（multipart：`audio`、`purpose`） |
| `POST /api/reference-audio/inspect` | 检查已有文件（`path`）或整个语料目录（`directory`） |

## 八、验收证据

`scripts/reference_audio_verify.py` 全绿（16 项断言）：

1. 厂商 18 条 prompt 中**只有**那条真削波的被否，且否在 `clipping` 上。
2. 用户 64 切片语料整体 `ok`（281.7 s）；同一份语料的**单个切片**判 `fail`——证明判对单位是必须的。
3. 6 条窄带副本**全部**被否，且都是 `bandwidth` 触发；真实与窄带之间间隔 **24.9 dB**。
4. 4 条硬削波副本全部被否（`clipping_run` 32–37）。
5. 干净拼接语料 `ok`；注入真 10 dB 噪声**被否**、真 20 dB **被警告**。
6. 语料总时长等于各文件之和（时长加权，不是文件计数）。

单测 31 条（`backend/tests/test_reference_audio.py`）+ 前端 16 条
（`frontend/src/composables/referenceAudio.test.ts`）。
