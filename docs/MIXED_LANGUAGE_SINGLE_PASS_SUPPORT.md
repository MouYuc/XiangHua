# 五语种单次混合合成支持手册

这份手册面向使用、验收和排查。当前验收基线是不含缩略词的五语种混合：D 组模型试听评分 `7/10`。目标模式是：一条台词一次提交、一次神经推理、一个连续音频文件。缩略词和旧 adapter/EOS 实验不属于当前支持范围。

## 1. 输入格式

支持五种显式语言标签：

| 标签 | 语言 | 典型文本 |
|---|---|---|
| `<zh>...</zh>` | 普通话 | `你好，欢迎回来` |
| `<yue>...</yue>` | 粤语 | `我记得佢今日喺屋企` |
| `<en>...</en>` | 英语 | `Voice Lab is ready` |
| `<ja>...</ja>` | 日语 | `こんにちは` |
| `<ko>...</ko>` | 韩语 | `안녕하세요` |

未标记文本按合成页默认语言处理，默认是普通话。标签只控制发音语言，不负责翻译。

示例：

```text
<zh>你好，</zh><yue>我记得佢今日喺屋企，</yue><en>AI Voice Lab is ready.</en><ja>こんにちは。</ja><ko>안녕하세요。</ko>
```

标签之间不要嵌套或交叉；每个开始标签必须有对应的结束标签。

## 2. 参考音频要求

参考语言和参考文本必须与参考音频内容一致。目标文本可以是五语种混合，但参考音频仍然是一个音色提示，不会自动为每种语言提供母语口音。

建议先用清晰、稳定、无背景音乐的参考音频验收音色，再单独比较语言发音。模型训练数据中缺少某种语言时，单靠标签不能创造该语言的母语韵律。

## 3. 严格单次模式的判定

调试日志中应看到：

```text
synthesis_mode=single_pass_explicit
segment_count=5
acoustic_inference_calls=1
```

`segment_count` 可以大于 1，但 `acoustic_inference_calls` 必须为 1。看到 `auto`、`auto_yue` 或多个独立音频片段，说明当前走的是兼容/诊断路径，不是严格模式。

## 4. 五语种验收清单

先验收固定句：

```text
<zh>你好</zh><yue>早晨</yue><en>Voice Lab</en><ja>こんにちは</ja><ko>안녕하세요</ko>
```

再验收反向顺序，例如：

```text
<ko>안녕하세요</ko><ja>こんにちは</ja><en>AI Voice</en><yue>我记得佢</yue><zh>欢迎回来</zh>
```

每次记录：原文、标签解析结果、规范化结果、每段 phone 数、最终音频时长、试听结论和 ASR 结果。进入引擎前，非末段的终止性标点只会从内部 `pronunciation_text` 去除，用户可见 `text`、历史和下载元数据保持原样；最后一个片段的句末标点保留。重点听四类问题：

- 后续语言被读成前一段语言；
- 边界处吞字、抢读或停顿过短；
- 英语片段的普通单词连接和重音；缩略词 `AI` 等暂不作为基线验收项；
- 粤语汉字被普通话化，或日语/韩语片段被跳过。

## 5. 常见问题

### 标签写了但仍然被自动识别

检查日志是否为 `single_pass_explicit`。如果是 `legacy_auto` 或 `compat_auto`，标签会在引擎内部重新进入自动分段器，不能用于判断显式标签方案。

### 粤语变成普通话

确认片段是 `<yue>...</yue>`，且没有被渲染成 `zh`。检查显式编译日志中的 `lang=yue` 和粤语 G2P 输出。不要通过增加空格或逗号来“提示”模型，空格不能改变自动语言映射。

### 缩略词读法异常

这属于已归档的独立研究问题，不用于判断当前五语种混合基线是否成功。不要通过展开成完整单词来规避问题，也不要把旧拼接或 adapter 结果混入当前试听评分。需要恢复时，先在新的实验目录中固定输入和模型，再单独记录报告。

### EOS 与非末段标点

生产默认使用可解释的混合 EOS 上下限：最低门槛为 `max(11, ceil(target_phone_count * 1.5))`，最大 token 数为 `max(minimum, ceil(target_phone_count * 2.5))`。上限用于防止模型在未采样 EOS 时继续复读尾句；普通单语言路径不受影响。WebUI 采样参数面板允许将 `mixed_eos_floor` 和 `mixed_token_cap` 留空以使用上述动态默认，或填写数值覆盖并保存；`mixed_eos_floor=11` 仍建议只用于诊断实验，不应盲目固定为生产值。非末段 `。！？!?…` 等终止标点由语言边界 pause（默认 120ms）承担分隔，末段标点不改写。

### 文本太长

严格单次模式不会偷偷拆成多次声学推理。若预处理后的文本超过当前 BERT/模型上下文限制，应缩短一条台词，或明确切换到兼容模式进行对比。

### 某个片段没有声音

检查该片段是否只有标点、是否包含目标语言可读脚本，以及 G2P 是否返回空 phone。错误应定位到片段序号，不应生成一个静音文件掩盖失败。

## 6. 开发者排查顺序

1. 查看解析后的 Segment IR，确认语言顺序和文本没有改变。
2. 查看规范化文本，确认广普转换只发生在 `zh`。
3. 查看 G2P 日志，确认每段使用声明语言，且没有调用 `LangSegmenter`。
4. 检查合并后的 phone/BERT 长度和边界索引。
5. 检查 `TTS.run()` 的声学推理调用计数是否为 1。
6. 最后才比较采样参数、参考音频和模型训练质量。

## 7. 兼容与回滚

旧的无标签单语言台词继续使用原有接口。需要和旧结果对比时，显式启用 `compat_auto` 并在实验记录中标注；它不代表标签已经生效。

回滚显式混合路由不会删除标签解析和校验逻辑，也不会修改模型权重。重新部署时应一并应用 GPT-SoVITS 文本预处理补丁，并记录补丁对应的引擎版本。
