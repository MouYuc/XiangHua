# 方言前端吞字缺陷审计（实测结论）

更新时间：2026-09-24
审计工具：`scripts/frontend_lexicon_audit.py`
JSON 输出：`output/frontend_lexicon_audit.json`

这份文档记录**实测**结论，取代此前 `DIALECT_PHASE1_BASELINE.md` 里"补前端词典"那几条
只凭 4 条探针得到的印象式判断。

## 一、吞字的完整链路（已定位到具体代码行）

```
普通话文本
  → g2pw 得到普通话拼音                      (00_pinyin)
  → fix_erhua 儿化修正                        (01_fix)
  → hanzi2dialect_pinyin  字级方言拼音映射    (02_hanzi)
  → word2dialect_pinyin   词级替换 + 连读 # 标记 (03_word)
  → liandu_tone           方言连读变调，改写声调号 (04_liandu)
  → pinyin2ipa            方言拼音 → IPA      (05_ipa)
  → ipa_tone              声调曲线 → ᴴ/ᴹ/ᴸ 字母 (06_ipa_format)
  → ipa_to_model_text     套 [ ] 查 vocab.txt
```

两个**互相独立**的静默丢失点：

### 缺陷 A：字不在 hanzi 表 → 回退普通话拼音 → 变调后必然查不到

`hanzi2dialect_pinyin.py:69`

```python
return polyphonic_map.get((text_unit, pinyin_unit), simple_map.get(text_unit, pinyin_unit))
```

字不在表里时**保留普通话拼音，不报错**。随后 `liandu_tone` 按方言规则改写声调号，
产出一个只在普通话里成立、方言 syllable 表里不存在的形式。

上海实例（探针 probe002 / probe004 实测）：

| 字 | 普通话拼音 | 上海 hanzi 表 | 变调后 | syllable 表 |
| --- | --- | --- | --- | --- |
| 这 | zhe4 | **缺失** | `zhe7` / `zhe10` | 查不到 |
| 尾 | wei3 | **缺失** | `wei10` | 查不到 |
| 什 | shen2 | **缺失** | `shen10` | 查不到 |
| 没 | mei2 | 缺失（只有 mo4→mmeh5） | `mei11` | 查不到 |

**上海是重灾区，根因是 hanzi 表严重欠填充**：

| 方言 | `hanzi.xlsx` 唯一字数 | syllable 表 `zh/ch/sh` 键数 | zh/ch/sh 覆盖 |
| --- | --- | --- | --- |
| 南京 | 6982 | 706 | 有 |
| 成都 | 5715 | 660 | 有 |
| 青岛 | 4537 | 756 | 有 |
| **上海** | **2842** | **0** | **完全没有** |

上海实测缺失的常用字：**这 尾 什 她 它 了 人**。
吴语无翘舌音，上海 syllable 表里一个 `zh/ch/sh` 键都没有，所以回退来的 `zhe*` 100% 落空。

### 缺陷 B：pinyin2ipa 把未命中项原样当 IPA 吐出

`pinyin2ipa.py:21-23`

```python
if base not in p2i_dict:
    unmatched_set.add(base)
ipa = p2i_dict.get(base, base)   # ← 回退成拼音原文
```

不抛异常、不跳过，而是把 `zhe7` 这个**拼音串**写进 IPA 字段。
`ipa_to_model_text` 再按空格切分套 `[ ]`，模型词表没有 `[zhe7]`，静默丢弃。
`*.log` 里有记录，但音频就是短了。

## 二、缺陷 B 之外的第三类：IPA 合法但模型词表没有

`syllable.xlsx` 产出的 IPA，`diamoe_tts/data/vocab.txt`（**440 个括号条目**）里没有。
这不是前端 bug，是前端音素表与已发布声学模型的不匹配，只能做音素重映射。

实测（`bad_ph` 列）：

| 方言 | 词表缺失音素数 | 典型缺失音素 |
| --- | --- | --- |
| 上海 | 46 | `ˈaᴸ` `ˈiᴴ` `ˈoᴴ` `ˈuᴴ` `ˈyᴴ` `ˈøᴴ` `ˈŋ̍ᴸ` `ˈăᴴᴴ` |
| 南京 | 13 | `ĕ` `ĭ` `ŭ` `y̆` `ɑ̆` `ɻ̍̆` `ˈoᴴ` `ˈɑᴹ` `ˈɚᴴ` `ˈn̩ᴹᴴ` |
| 青岛 | 12 | `o̯` `ɯ` `ˈɯᴴᴴ` `ˈɯᴸᴹ` `l̻` `t͜θʰ` `ɘ` `ɪ̯ᴹᴸ` |
| 武汉 | 2 | — |
| 西安 / 郑州 / 普话 | 1 各 | `ˈn̩ᴹᴴ` |
| 成都 / 石家庄 | **0** | — |

注意两个模式：

1. **多字声调标记**：模型词表里是 `ᴴᴹ` 这类**双字母**调符，但部分方言的 `tone.xlsx`
   把某些调值映射成**单字母**（`¹² → ᴸ`），于是 `ˈaᴸ`、`ˈiᴴ` 这类词表里不存在。
   这是前端调符表与模型词表的口径差异。
2. **青岛的 `o̯` `ɯ` 是纯音段音素**，与声调无关，必须重映射到词表内最接近的音素。

## 三、审计工具修正的两个方法论错误

初版审计报出大量假阳性，因为两处没复刻上游语义：

1. **`word.xlsx` 的值是多音节串**。`word2dialect_pinyin.py:107` 的 `apply_replacements`
   把 N 个字的拼音单位合并成 **1 个**字符串（`阿姨` → `a4 yi2`，用 `""` 占位补足对齐）。
   必须按空白拆开逐音节查表。修正后 `miss_fam` 从 209 降到 **0**。
2. **不能拿带数字调值的表直接比词表**。`ipa_tone.py:13-17` 是按 `tone.xlsx` 的
   `contour → mark` 做**全行普通字符串替换**；不过这一层，每个带调韵母都会被误报为缺失。
   已在 `syllable_tokens()` 里复刻该替换（含 Excel 行序）。

另：`syllable.xlsx` 的 `initial` / `final` 两列中，**`final` 自身含逗号**
（`shou6` → initial=`ʃ`, final=`o̯,ˈʊ³¹`）。上游拼成 `f"{initial},{final}"`
再把逗号换成空格，所以一个音节会变成多个空白 token，逐个查词表。

## 四、`#...#` 是连读块，不是丢字

`word2dialect_pinyin.py:49-51` 把匹配到的连读词包成 `#词#`，拼音侧同时包成
`#拼音串#`。`pinyin2ipa` 用 `item.strip("#")` 处理。所以「2 字 → 1 个 IPA 单元」
是**设计行为**。郑州 probe004 的 `#这个#` / `#没有#` 属此类，
**郑州并没有吞字**——`DIALECT_PHASE1_BASELINE.md` 里"郑州少掉的音节"一句与它自己
的表格（覆盖率 100%）矛盾，是笔误。

## 五、审计工具的已知盲区

当前审计只扫 `hanzi.xlsx` / `word.xlsx` 引用的音节，因此**漏掉由 `liandu_tone`
新造出来的声调变体**（如南京的 `me5`：syllable 表只有 `me1/2/3/4/6`，
变调产出 `me5` 后落空）。

补法：对每个方言，取 syllable 表的**音节家族集合** × **该方言 tone 表出现的调号集合**
做笛卡尔积，差集即潜在缺口。这是静态可算的，不需要跑合成。

## 六、修复方向（按可靠度排序）

1. **优先做音素重映射（缺陷 C）**——它不依赖任何新语言学数据，纯工程，
   且青岛/上海/南京的缺失音素清单已经确定。做法：在 `ipa_to_model_text`
   前插一层 `frontend IPA → model IPA` 归一化表，把词表外音素映射到词表内最近音素，
   并把映射记入结果，任何映射都必须可见、可审计，不许静默。
2. **上海的 hanzi 表补字（缺陷 A）**——不能凭空造上海话读音。
   可靠来源是 DiaMoE 官方放出的 **IPA 标注训练集**
   （`RICHARD12369/DiaMoE-TTS_IPA_Trainingset`，含 KeSpeech 上海数据），
   可由「汉字 ↔ IPA」对齐**反推**作者自己口径下的 hanzi→方言拼音条目。
3. **声调家族笛卡尔积补齐**——补 `me5`、`zhe7` 这类变调产物的调号变体。
4. **加回归门**：`frontend_lexicon_audit.py` 进 CI，任何 `bad_ph` / `miss_fam` 增长即失败。

## 七、不要做的事

- 不要凭空发明方言 IPA 或上海话读音。找不到权威来源就**显式标注缺口**，不要填。
- 不要修改 `third_party/DiaMoE-TTS` 里的 xlsx 后不记录来源与依据。
- 不要把「ASR CER 低」当成方言正确：CER 度量的是「像不像普通话」，
  方言味越足 CER 越高，方向是反的（见 `DIALECT_PHASE1_BASELINE.md`）。

# 第二轮实测修正与修复（2026-09-30）

## 八、缺陷 C 已修复：IPA → 模型词表归一化

新增两个文件：

| 文件 | 作用 |
| --- | --- |
| `scripts/ipa_vocab_normalize.py` | 规则生成器 + 复核入口（`--build` / `--check` / `--explain`）|
| `assets/ipa_vocab_remap.json` | 生成出的归一化表（**运行期只读数据**，便于逐条复核）|

接线位置：`scripts/diamoe_runtime.ipa_to_model_text()`，在查词表前先归一化，
并新增 `return_trace=True` 返回逐步映射记录。**归一化表缺失不报错**，
退化为原有行为，由审计工具负责报告损失。

### 规则顺序（每条都必须落到确实存在于词表中的 token）

| 规则 | 条数 | 是否改声调 |
| --- | --- | --- |
| `strip_diacritic` 去掉模型没用过的附加符 | 17 | 否 |
| `add_breve` 补回短音符 | 20 | **否（调符原样保留）** |
| `expand_checked_tone` 单字母调符补成同调阶双字母 | 14 | **否（保调阶）** |
| `nearest_contour` 按 H/M/L 调阶距离取最近调符 | 3 | **是（唯一会改的）** |
| `substitution` 音段替换（有仓库内证据） | 9 | 否 |
| `glide_tone_move` 把调号从滑音尾搬回韵母 | 1 | 否 |

**关键洞察**：词表的单字母调符（`ᴴ`/`ᴹ`/`ᴸ`）**只出现在带短音符 `̆` 的短元音上**，
而前端部分表漏写了短音符（上海 `a12 -> ˈaᴸ`，但同表的 `ah*` 行都写了 `ă`）。
所以最大的一类修复**根本不需要替换音素，只需要补一个音长符号**，且声调完全不变。
把这两条规则放在「编辑距离」之前，**改声调的映射从 17 条降到 3 条**。

### 音段替换的依据（都不许凭空来）

| 前端 | 模型 | 依据 |
| --- | --- | --- |
| `ɯ` | `ɹ̩` | 仅青岛用它表示齿音 `θ`/`t͜θ`/`t͜θʰ` 后的舌尖元音（si/zi/ci，18 条）；青岛自己用 `ɻ̍` 表示卷舌后的 zhi/chi/shi/ri。**其余八个方言表对同一批 si/zi/ci 全部写 `ɹ̩`**（如上海 `ci1 -> t͜sʰ,ˈɹ̩⁵²`）|
| `ɨ` | `i` | 仅武汉 10 条，全是零声母 `ii1..ii5`（即普通话 yi）；武汉自己用 `ɹ̩` 表示 si。其它方言同一音节写 `i` |
| `ɘ` | `ə` | 青岛 204 条（en 等）；词表**已有** `ˈɘᴴᴴ` 等带调形式，仅缺无调形式 |
| `t͜θʰ` | `t͜sʰ` | 青岛 408 条，与 `t͜θ` **构成送气对立**（草 /t͜θʰ/ 对 早 /t͜θ/）。映射到 `t͜θ` 会丢掉送气、把草与早合并，所以**不取最小编辑距离那条** |

### 序列级修复：青岛表的调号挂错位置

```
bei1  final='ˈe¹¹³,ɪ̯'      ← 调号在韵母上
bei5  final='e,ɪ̯'          ← 无调
bei6  final='ˈe,ɪ̯³¹'       ← 调号跑到了滑音尾上（表内笔误）
beir6 final='ˈɚ³¹'          ← 同一音节的儿化形，调号又回到韵母上
```

`ɪ̯ᴹᴸ` 因此**无法用 token→token 映射表达**，需要看相邻 token：把调号从滑音尾搬回裸露的
带重音韵母（`ˈe` + `ɪ̯ᴹᴸ` → `ˈeᴹᴸ` + `ɪ̯`）。仅当两个结果 token 都在词表内才执行。

## 十、仍然存在：缺陷 A（原始拼音泄漏）

上海 5 个、南京 1 个 token 仍然丢弃，全部是**漏查的原始拼音串**
（`zhe7 zhe10 wei10 mei11 shen10` / `me5`），不是音素映射能解决的：

1. 字不在 `hanzi.xlsx` → `hanzi2dialect_pinyin.py:69` 保留普通话拼音；
2. `liandu_tone` 把调号改写成方言调号（`zhe4`→`zhe7`）；
3. `pinyin2ipa.py:23` 查不到就把拼音串当 IPA 吐出；
4. `ipa_to_model_text` 丢词。

**修法只有一条：补前端表**（`hanzi.xlsx` 与 `syllable.xlsx` 的声调变体），
需要真实方言读音数据。当前**数据获取受阻**（见下）。

## 十一、数据获取现状（2026-09-30 实测）

| 来源 | 状态 |
| --- | --- |
| HuggingFace | **网络不可达**（443 超时）|

## 十二、下一轮修复方向（更新）

1. **缺陷 A 补字**——石家庄（3611）与上海（2361）优先。需要先解决数据来源：

# 第三轮：跑真实前端量化，并修掉缺陷 A（2026-10-07）

## 十三、为什么必须跑真实前端

表格扫描有**两个盲区**，前面的结论因此既高估又低估过缺陷 A：

1. `hanzi2dialect_pinyin.py` 回退普通话拼音后，`liandu_tone` **会改写声调号**（`zhe4`→`zhe7`）。
   这个产物在**任何表里都不存在**，扫描表永远看不到它。
2. 回退到普通话拼音后**到底响不响**，取决于该方言的 `syllable.xlsx` 里有没有这个音节。
   只有跑一遍才知道。

新增 `scripts/frontend_loss_sweep.py`：直接跑厂商的六段流水线，然后问三个问题。

- **厂商自己报了吗？** `pinyin2ipa.py` 本来就会在输出旁写 `.log`，里面有
  `[Summary of pinyin mapping items not found]`。**这个文件此前没有任何代码读过**——
  前端一直在自我诊断，只是没人看。
- **字进模型词表了吗？** `pinyin2ipa.format_ipa_output` 是**先插 `|` 再把逗号换成空格**，
  所以最终 IPA 按 `|` 切开恰好**一个 chunk 对应一个输入字**。句子语料因此和单字语料一样可逐字归因。
- **归一化表救回来了吗？** 同一个 token 分别用空 remap 和真实 remap 打两次分。

两个刻意的设计选择，防止数字虚高：

- **语料的普通话读音用方言表自己声明的那条**。上海表把「占」只收在 `zhan1` 下，
  若喂 G2P 的首选读音 `zhan4` 就会「泄漏」——但表并不缺这个字，缺的是另一条读音。
  用表声明的读音量的是**流水线的最好情况**；单字 G2P 必然选错的那类（多音字暴露面）
  直接从表 + G2P 算，不跑流水线，单独统计。
- **不用上游第 0 步**。`gen_ppinyin_oop.py` 要一个仓库里根本没发布的 g2pW ONNX，
  路径写死成占位符 `path/to/g2pW_model/g2pw.onnx`。普通话拼音改用 `pypinyin`（带调号数字，轻声 5）；
  `pypinyin` 对扩展区生僻字会把字原样吐回（`㓕5`），这类行**排除并计数**，否则等于拿 G2P 的缺口去指责方言前端。

语料：仓库 `docs/*.md` + `AGENTS.md` 里切出的 158 句中文（均 19.0 字），只保留
汉字与中文标点，保证一字一 token。

## 十五、修复：缺陷 A 用普通话 IPA 兜底（已实测生效）

修法**不是**编方言读音——表里确实没有，编出来就是伪造。用的是**厂商自己发过的表**：
`frontend/dialect/putonghua/base_syllable.xlsx`（普通话拼音→IPA）
与 `base_tone.xlsx`（普通话调型→调符）。方言念不出来的音节**改用普通话念出来，而不是不念**。

- 与第十二节第 3 条既定策略一致：**宁可念错，不可吞字**。
- 音节数不变 ⇒ F5 由文本长度推导的时长预算不变，节奏不受影响。
- 落地为 `scripts/frontend_ipa_repair.py`，是一个**后处理**，不改 `third_party` 任何文件。
  原因是普通话声调会被 `liandu_tone` 的变调**改写掉**，所以必须从**第 2 段**（查字之后、变调之前）
  取原始普通话读音，再回填到最终 IPA。命中位置做**内容校验**（该 chunk 必须仍是原始拼音串）
  且**行 chunk 数必须等于字数**，否则整行跳过并计数，绝不盲改。

修复后重跑同一语料：

| 方言 | 丢字行（修前 → 修后） | 原始拼音泄漏 | 普通话兜底音节 |
| --- | --- | --- | --- |
| **上海** | **182 → 11** | **131 → 0** | **131** |
| 南京 | 52 → 11 | 1 → 0 | 1 |
| 成都 | 51 → 11 | 0 | 0 |
| 其余 6 个 | 51/46 → 11 | 0 | 0 |
| 普通话（对照） | 51 → 11 | 0 | 0 |

**修复后 9 个方言的丢字行数与普通话对照组完全一致（11 行）**，
即**方言特有的确定性吞字已归零**。频率最高的兜底字：这 14、生 10、再 9、声 8、认 7、告 6。

## 十六、缺陷 D：8 个中文标点被静默丢弃

`ipa_to_model_text` 只在 `[token]` 命中 IPA 词表或标点表时保留 token。
实测 `； ： （ ） “ ” ‘ ’ 【 】 ( ) [ ]` **两张表都没有**，因此在送进 tokenizer 之前就被丢掉。
其中括号引号（`（）【】()[]“”‘’`）**丢得对**——它们只做分隔、不表停顿，模型没有对应符号；
但 `；` 与 `：` **是表停顿的**，丢了会压平韵律。

修法：`ipa_vocab_normalize.PUNCTUATION_ALIASES` 把 `；`→`，`、`：`→`，`（模型有逗号），
并把括号引号写进 `PUNCTUATION_DROPPED_ON_PURPOSE` 显式记录为**刻意丢弃**。
修复后剩余 11 行丢字全部是 `“ ” （ ）`，即刻意丢弃项。
