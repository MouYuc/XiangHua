# 音色唱歌（SVC）客观评测

## 一、为什么必须自建基准

kNN-VC 的原论文（Baas, van Niekerk & Kamper, *kNN-VC: Non-parametric voice conversion
with k-nearest-neighbor regression*, Interspeech 2023, **arXiv:2305.18975**）**只做语音，
没有任何歌声实验**。所以本项目「音色唱歌」这一半是外推，没有可引用的基线，
也没有可抄的阈值。

本文把这段外推变成实测，并且**先把尺子校准再用尺子**。

## 二、两个问题必须分开问

一个转换器可以只做到一半，所以两个问题分别测：

| 问题 | 怎么测 | 失败长什么样 |
| --- | --- | --- |
| **旋律还在吗？** | 转换结果的音高曲线对比**源音频**：音分误差、对数 F0 相关系数、清浊判定错误率 | 复读机：原样输出，旋律完美，但音色没变 |
| **音色换过去了吗？** | **独立**说话人验证模型算 SECS | 目标音色的噪声：音色像了，旋律没了 |

外加一个**恒等对照**：把源音频拿去和**它自己**的帧做 kNN（topk=1），最近邻就是自己，
于是剩下的音高损伤全部是**声码器**造成的，与转换无关。没有这个对照，
一个差的音高分数无法归因。

## 三、尺子的校准：CREPE 对人工标注

Vocadito（Bittner, Pasalo, Genchel, Yip & Kim, *Vocadito: A Dataset of Solo Vocal
Recordings for Transcription Tasks*, TISMIR 2022）提供 40 段独唱 + **人工标注 F0**。
40 段全跑，全部对齐到估计器的时间栅格：

| 指标 | CREPE（full） | pYIN |
| --- | --- | --- |
| 中位绝对音分误差 | **8.64** | 19.30 |
| p95 绝对误差 | 27.59 | 105.46 |
| **原调准确率 RPA**（±50 音分） | **0.982** | 0.820 |
| 音级准确率 RCA（折叠八度后 ±50 音分） | 0.983 | 0.830 |
| 八度错误率 | **0.0013** | 0.0018 |
| 100 音分内 | 0.988 | 0.944 |
| RMSE | 222.03 | 179.25 |
| RMSE（折叠八度后） | 42.05 | 53.60 |
| 清浊判定准确率 | 0.680 | 0.830 |
| 清浊精确率 / 召回率 | 0.850 / **0.579** | 0.807 / **0.980** |

**CREPE 的音高精度足以当尺子**（中位 8.6 音分、RPA 0.982）。
跨估计器对比：40 段配对，中位误差相差 10.93 音分，清浊准确率相差 0.13。

### RMSE 为什么必须与折叠值、八度错误率一起报

上表里 CREPE 的 RMSE 是 222 音分，而中位误差只有 8.6 音分。
**少数几帧的八度错误就能把 RMSE 拉高几百音分，而中位完全不动。**
所以采用 `mir_eval` 的标准配对（Raffel et al., ISMIR 2014）：
**RPA 与 RCA 的差值本身就是八度错误率**，另外单列 `octave_error_rate` 与折叠后 RMSE。
只看 RMSE 会把一个旋律跟得很好的估计器判成灾难。

## 四、清浊阈值：一次失败的调参（如实记录）

torchcrepe 示例里的 `periodicity ≥ 0.21` 在 Vocadito 上只召回 **0.579** 的浊音帧。
于是扫了 0.02–0.60 共 30 个阈值：

```
阈值   0.02 → 准确率 0.6509  精确率 0.6880  召回率 0.5887
阈值   0.21 → 准确率 0.6783  精确率 0.7349  召回率 0.5876
阈值   0.60 → 准确率 0.7040  精确率 0.7879  召回率 0.5756
```

**召回率从 0.02 到 0.60 一直卡在 0.58 附近，调阈值根本动不了它。**
提高阈值只是把更多帧判成清音、换来一点精确率。结论是：
**问题不在阈值，而在「浊音」的定义** —— Vocadito 标注把气声起音、滑音进出都算浊音，
CREPE 的周期性在这些帧上确实低。所以**保留上游默认值 0.21**，
并把「扫过、无效」这件事记在代码注释里，而不是从一条平掉的曲线里挑个"最优值"冒充标定。

**这对 SVC 指标没有影响**：源音频与转换结果用的是同一个估计器、同一个阈值，
系统性的清浊偏置在**差值**里相互抵消。恒等对照实测清浊错误率中位 0.355（相对源），
而绝对清浊准确率只有 0.68 —— 差值比绝对值小，正说明偏置确实被抵消了。

## 五、独立 SECS：不能用转换自己的特征当证据

kNN-VC 的转换建立在 **WavLM-Large 第 6 层特征**上。用它自己的特征去问
「转换后像不像目标音色」是**循环论证**：输出就是那个空间的最近邻查找，相似是构造必然。

所以音色用的是完全不同的模型：`ERes2NetV2`（WeSpeaker / 3D-Speaker 家族，
Kaldi fbank 特征），与声码器路径**不共享权重、不共享特征、不共享训练目标**。
本机已有权重，无需下载（`GPT_SoVITS/pretrained_models/sv/pretrained_eres2netv2w24s4ep4.ckpt`）。

**先验证这把尺子能分辨人**：

| 对比 | SECS |
| --- | --- |
| 同一说话人的两个切片（用户音色） | **+0.8816** |
| 用户 vs 上海男声 prompt | +0.3362 |
| 用户 vs 成都女声 prompt | +0.2923 |
| 两个不同 prompt 说话人之间 | +0.3510 |

同人 0.88 / 异人 0.26–0.35，间隔清楚，尺子可用。

## 六、代价最小的对照：恒等转换

把源音频和**它自己的帧集**做 kNN（topk=1），最近邻就是自己，
于是输出 ≈ 源音频经过同一套声码器。这样得到的音高损伤是**声码器的**，
不是转换的。没有这个对照，下面「转换后差了一个八度」无法归因。

## 七、实测结果（8 段 Vocadito，topk=4，24 个参考切片 / 4410 帧 / 88.2s）

### 音色：成功，而且每条都成功

| 指标 | 中位 | 范围 |
| --- | --- | --- |
| 转换结果 vs 目标音色 | **+0.6069** | [0.5385, 0.6432] |
| 源音频 vs 目标音色（未处理基线） | +0.2739 | [0.2214, 0.4745] |
| 恒等输出 vs 目标音色 | +0.2889 | [0.2645, 0.3862] |
| **相对源音频的提升** | **+0.3224** | [0.1376, 0.3797] |

**这是明确的正面结论**：kNN-VC 在歌声上确实把音色换过去了，
8 段全部提升，没有一段例外；而且恒等对照（0.289）与源音频基线（0.274）几乎一样，
说明提升确实来自 kNN 匹配而不是声码器。

### 音高：旋律轮廓部分保留，但**整体移调约一个八度**

| 指标 | 转换结果（5/8 可测） | 恒等对照（6/8 可测） |
| --- | --- | --- |
| 中位绝对误差 | 1061.4 音分 | 91.5 音分 |
| **中位移调量** | **−1061.4 音分** | +37.9 音分 |
| 对数 F0 相关系数 | 0.626 | **0.972** |
| 原调准确率 RPA | 0.000 | 0.264 |
| 音级准确率 RCA | 0.139 | 0.264 |
| 八度错误率 | 0.080 | 0.000 |
| 清浊判定错误率 | 0.227 | 0.356 |

逐条看得更清楚：

| 素材 | 源音频 F0 中位 | 转换后 F0 中位 | 恒等输出 F0 中位 |
| --- | --- | --- | --- |
| vocadito_10 | 124.3 Hz | 120.0 Hz（保持） | — |
| vocadito_11 | 244.6 Hz | **122.4 Hz（降一个八度）** | 239.9 Hz（保持） |
| vocadito_12 | 246.5 Hz | **119.3 Hz（降一个八度）** | 248.5 Hz（保持） |

**三条结论：**

1. **转换结果的音高落进了目标匹配池的音域。** 源音频 245 Hz 的女声被降到约 120 Hz，
   正是目标参考音的音域。原因直接可推：kNN 把每一帧映射到参考集里最近的帧，
   而 WavLM 特征里带有音高信息，于是**声码器重建的是参考帧的音高**。
   → **产品含义：用 kNN-VC 唱歌会改变调性，把旋律搬进目标音色的音域。**
   这不是 bug，是方法的性质；用户要么接受移调，要么先把源音频转调到目标音域。
2. **恒等对照说明声码器本身是保调的**：移调只有 +37.9 音分、相关 0.972。
   所以 −1061 音分的移调**完全来自 kNN 匹配**，不是声码器。
3. **声码器往返本身有约 91 音分的误差底**（中位绝对误差，偏置仅 +37.9 音分、
   相关 0.972，说明是围绕源音高的抖动而不是系统性偏移）。
   → **任何小于约 100 音分的转换误差都不可归因于转换**，这是这套测量的分辨率下限。

### 3/8 段"不可测"，必须如实计入

8 段里 3 段的音高曲线被判为不可信（见下一节），**不计入上表**。
把它们丢掉会美化结果，把它们算进去会伪造结果，所以单列。

## 八、一个真实且危险的失效：CREPE 在用户自己的录音上给出噪声

调试中发现的**最严重问题**：CREPE 在用户的参考切片上**完全不工作**。

| 音频 | CREPE 峰值周期性 | CREPE 中位 F0 | pYIN |
| --- | --- | --- | --- |
| Vocadito 独唱 | **0.9644** | 123.9 Hz | 0.914 浊音率，124.9 Hz |
| **用户参考切片** | **0.0166** | **2005 Hz（无意义）** | **0.674 浊音率，109.4 Hz** |

排查过的可能原因**全部排除**：不是采样率（32k/44.1k/16k 都一样）、
不是重采样库（librosa 与 torchaudio 一样）、不是电平（放大 2×/5×/10× 一样）、
不是直流偏置（去均值一样）、不是频率范围（`fmin/fmax` 改成默认值一样）、
不是设备（CPU/CUDA 一样）、不是窄带（把 Vocadito 降到 8 kHz 再升回来，CREPE 照样正常）。
pYIN 在同一段音频上给出干净的 109.4 Hz —— 所以音频是**有音的**，是 CREPE 认不出来。

**这正是不校准就会踩的坑**：如果只跑 CREPE，会得到一条"中位 2005 Hz"的曲线，
它看起来像数据，实际是噪声。所以：

1. 新增**退化判定** `F0Track.degenerate`：峰值置信度低于 `0.05` 即判为不可信。
   实测真实歌声 0.96、用户切片 0.0166，**相差三个数量级，界限不敏感**。
2. 不可信的曲线**不参与打分**，报告里写明原因，而不是产出一个数。
3. `svc_metrics.cross_check_estimators()` 同时跑 CREPE 与 pYIN（两者不共享代码与训练数据），
   一致才是证据。
4. 已核对：上一轮发布到参考音门禁里的音高覆盖检查用的是 **pYIN 而不是 CREPE**
   （`backend/services/reference_audio.py` 的 `f0_summary`），所以**不受此影响**。

## 九、刻意不做的事 / 已知限制

- **没有可用于对标的论文基线。** kNN-VC 论文无歌声实验，所以
  `svc_metrics.PROJECT_TARGETS` 里的阈值是**本项目自定的目标值**，
  在代码与报告里都明确标注"不是论文数值"。
- **只测了单声部清唱。** Vocadito 是无伴奏独唱。有伴奏、和声、说唱都不在覆盖范围内。
- **没有测音准本身。** 测的是"转换是否保持了源音频的音高"，不是"唱得准不准"。
- **没有测节奏/时长。** kNN-VC 逐帧替换，时长天然保持，所以没测。
- **移调问题没有修复，只是量化了。** 候选修法（转调源音频到目标音域、或按音高条件化匹配）
  都还没做，也没有验证。

## 十、怎么复现

```powershell
# 1) 尺子校准：CREPE / pYIN 对 Vocadito 人工标注
.venv\Scripts\python.exe scripts\f0_estimate.py --validate --json-out output\svc_eval\f0_validation.json

# 2) 清浊阈值扫描（结论：调不动，保留默认）
.venv\Scripts\python.exe scripts\f0_estimate.py --tune-voicing

# 3) 独立说话人模型自检（同人应高、异人应低）
.venv\Scripts\python.exe scripts\speaker_embedding.py <同人a.wav> <同人b.wav> <异人.wav>

# 4) 唱歌转换实验（含恒等对照）
.venv\Scripts\python.exe scripts\svc_experiment.py --limit 8 --topk 4 --reference-limit 24

# 5) 单条转换的完整指标
.venv\Scripts\python.exe scripts\svc_metrics.py --source <源歌声.wav> --converted <转换结果.wav> --reference <目标音色.wav>

# 6) 回归门
.venv\Scripts\python.exe -m unittest backend.tests.test_f0_estimate backend.tests.test_svc_metrics -v
```
